# ให้ PC1 มีช่องทางถาวร — self-hosted runner (2026-11-08)

K: *"ทำเองให้ได้ ... หาวิธีทำเอง"*

## ทำไมต้องเป็นวิธีนี้ (วัดจริง)

| ทาง | ผล |
|---|---|
| pod browser → Google login | ❌ ถูกบล็อก (`signin/rejected`) |
| Google **device flow** + Gmail scope | ❌ `invalid_scope` — Google ห้าม Gmail ผ่าน device flow |
| OAuth YouTube (4 token) scope | ❌ มีแค่ `youtube` — อ่าน Gmail ไม่ได้ |
| pod → `imap.gmail.com:993` | ✅ **เปิด** ⇒ เหลือแค่ **App Password** |
| PC1 funnel `/mcp` | ❌ 502 (backend `winremote-mcp` ดับ) |
| PC1 พอร์ต 22/3389/5900/8090/12000 | ❌ ปิดหมด |
| rendezvous host เก่าทุกตัว | ❌ ตายหมด (pod เก่าถูกเก็บ) |
| self-hosted runner ใน repo | ❌ ไม่มี (queued ค้าง) |

**ข้อสรุป:** pod สั่ง PC1 ตรง ๆ ไม่ได้เลย (ไม่มี inbound route) — และทุก host เก่าตายเพราะ
pod ถูก **รีไซเคิล + เปลี่ยนชื่อ**. ⇒ ต้องเป็นช่องทางที่ PC1 **dial ออกเอง** และ **ถาวร**

## วิธีแก้: GitHub Actions self-hosted runner บน PC1

PC1 dial ออกไป `github.com` (ต่อได้เสมอ) → pod dispatch workflow → งานไปรันบน PC1
**ไม่มี port forward, ไม่มี tunnel, ไม่มี inbound rule และรอด pod รีไซเคิล** (runner ต่อเองใหม่)

- ผมมีสิทธิ์ **admin** repo `kongkeat938/ax-workspace` (private) + ออก runner registration token ได้
- ติดตั้งเป็น **logon task** (ไม่ใช่ Windows service) เพราะ service account **มองไม่เห็น Chrome
  profile ของ user** — ซึ่งคือเหตุผลทั้งหมดที่ต้องใช้ PC1
- ลงทะเบียนกับ repo **private** โดยตั้งใจ: runner บน repo public ถูกสั่งรันโค้ดจาก fork PR ได้

## วิธีติดตั้ง — 1 คำสั่งบน PC1 (PowerShell **as Administrator**)

> **ขอ token สดจาก ak ก่อน** (token หมดอายุ ~1 ชม.) — อย่าเก็บในที่สาธารณะ

```powershell
iwr 'https://raw.githubusercontent.com/kongkeat938/ai-content-lab/main/ops/pc1_install_runner.ps1' -OutFile "$env:TEMP\pc1_install_runner.ps1" -UseBasicParsing; powershell -ExecutionPolicy Bypass -File "$env:TEMP\pc1_install_runner.ps1" -RepoUrl 'https://github.com/kongkeat938/ax-workspace' -Token '<TOKEN_FROM_AK>'
```

สำเร็จเมื่อเห็น `RESULT=OK` + `RUNNER_NAME=PC1`

## หลังติดตั้ง — ak ทำเองทั้งหมด (ไม่ต้องพึ่ง K อีก)

```bash
# 1) ดูว่า PC1 มาแล้วไหม + winremote ตายไหม
gh workflow run pc1-task.yml -R kongkeat938/ax-workspace -f task=status
# 2) ซ่อม winremote MCP บน PC1
gh workflow run pc1-task.yml -R kongkeat938/ax-workspace -f task=fix-remote
# 3) อ่านเมล์ (Chrome profile ที่ login ไว้)
gh workflow run pc1-task.yml -R kongkeat938/ax-workspace -f task=readbox -f label=ch2
```
