## อัปเดต 16:35Z — ปิด "จุดตาย" ตัวสุดท้ายแล้ว

**จุดตายที่พบ (วัดจริง):** watchdog chain (ตัวตั้งเวลา self-chaining) **ต้องมีคนกดเริ่มครั้งเดียว**
และ **ต่อคิวตัวถัดไปตอน "ท้าย" รอบ** → ถ้า link ถูกยกเลิก/หมดเวลา กลางทาง **chain ขาดถาวร**
และ **cron ของ GitHub ไม่น่าเชื่อถือ** (วัด: foreman cron `*/30` ยิงแค่ **1 ครั้งใน 30 runs**)

**แก้แล้ว:**
| ปัญหา | วิธีแก้ |
|---|---|
| link ตายกลางทาง → chain ขาด | **ต่อคิวตัวถัดไป "ก่อน" เริ่มทำงาน** → ตัวสำรองรออยู่แล้วเสมอ |
| ต้องมีคนกดเริ่ม | foreman ชุบเองเมื่อ chain เงียบ + watchdog มี backup schedule `45 */4` |
| rail ที่พึ่ง cron อย่างเดียว | foreman ขับ `check-duplicates`, `progress`, `short doors` เอง |
| short doors ล้มเพราะ quota | 403-quota = **เลื่อน ไม่ใช่ fail** (exit 0) |
| กันถอยหลัง | `scripts/test_watchdog.py` (รันใน foreman ทุกครั้ง) |

**ข้อจำกัดเดียวที่เหลือ (ยอมรับได้):** repo ไม่มี activity 60 วัน → GitHub **ปิด cron ทั้งหมด**
แต่ **chain ไม่พึ่ง cron** — พึ่ง `workflow_dispatch` ที่ต่อกันเอง ซึ่งยังทำงาน
(และงานมี commit ทุกวันอยู่แล้ว จึงไม่เงียบ 60 วัน)
