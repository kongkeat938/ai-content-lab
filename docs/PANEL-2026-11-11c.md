### 1. ต้นทางของสตรีมปริศนา (เรียงตามความน่าจะเป็นสูงสุด)

*   **อันดับ 1: โทเค็น (OAuth2 Refresh Token) รั่วไหลไปอยู่ที่ระบบภายนอก (เช่น Zapier, Make, หรือเซิร์ฟเวอร์เก่าที่ยังรันอยู่)**
    *   *เหตุผล:* การยิง API ตั้งเวลาโพสต์ด้วย fixed cadence (`:21`) และยังใช้ Metadata เก่า (`en-US`, หมวด 27, แบรนด์เก่า) เป็นลายเซ็นชัดเจนว่ามีโปรแกรมภายนอกเกาะติดบัญชีอยู่ผ่าน Token ชุดเดิม
    *   *วิธีพิสูจน์ (Single Measurement):* ไปที่ Google Cloud Console > APIs & Services > Credentials ดึงรายการสิทธิ์ที่เชื่อมต่อ (Authorized apps/tokens) และตรวจดู Audit Log ของ Google Cloud ว่า IP ใดเรียกใช้ YouTube Data API `videos.insert` ในนาทีที่ `:21` ของทุกชั่วโมง
*   **อันดับ 2: แพลตฟอร์มภายนอก (เช่น Make.com / Zapier / Buffer) ที่เคยตั้งค่า Auto-publish ไว้แล้วลืมปิด**
    *   *เหตุผล:* บัญชีเหล่านี้มักมีค่า Default เป็นหมวดหมู่ 27 และภาษาอังกฤษ (`en-US`) ตามเทมเพลตสากล
    *   *วิธีพิสูจน์:* ล็อกอินเข้า Dashboards ของ Third-party automation tools ทุกตัวที่ทีมเคยใช้ แล้วเช็คประวัติการทำงาน (Execution History) ย้อนหลัง

---

### 2. การตอบสนองที่เหมาะสม (Proportionate Response แบบไร้มนุษย์)

ทำทั้ง 3 ข้อนี้ทันทีเพื่อตัดวงจรความเสียหาย โดยไม่ต้องใช้คน:

1.  **Revoke & Rotate Tokens ทันที:** สั่งเพิกถอน (Revoke) OAuth2 Refresh Token ทั้งหมดใน Google Cloud Console แล้วสร้างชุดใหม่ใส่เข้าไปใน GitHub Actions Secret ของพี่ทันที สตรีมผีจะตายสนิทในนาทีถัดไปเพราะยิง API ไม่ผ่าน
2.  **Auto-Take-Down (เฉพาะคลิปผี):** เขียนสคริปต์สั้นๆ รันผ่าน GitHub Actions เช็คว่าวิดีโอไหนในช่องที่ *ไม่มี* ID บันทึกอยู่ใน `content/<ch>_*.json` ของเรา ให้สั่งเรียก YouTube API `videos.delete` ลบทิ้งอัตโนมัติทันที
3.  **ห้ามทำ:** **อย่า**กดลบช่องทิ้ง หรือ **อย่า**เปิดใช้งานฟีเจอร์แปลภาษาอัตโนมัติของ YouTube เพราะจะกระทบกับระบบหลักที่รันอยู่

---

### 3. ยามเฝ้าระวังที่ถูกและทนที่สุด (Durable Guard & Fail Condition)

*   **ตัวยามเฝ้าระวัง:** เพิ่มขั้นตอนเช็คความปลอดภัย (Guard Step) ไว้ใน GitHub Actions ตัวเดิม ก่อนที่มันจะจบ Workflow ประจำวัน ให้สคริปต์เรียก YouTube Data API `search.list` หรือ `channels.list` เพื่อดึงรายชื่อวิดีโอล่าสุดทั้งหมดบน YouTube จริงๆ มาเทียบกับไฟล์ Manifest ใน Repo
*   **เงื่อนไขที่ต้องสั่ง FAIL:** ถ้ายอดรวมวิดีโอออนไลน์บนช่อง **มากกว่า** จำนวน ID ที่ถูกบันทึกไว้ใน Manifest ของเราแม้แต่คลิปเดียว ให้ **Workflow สั่ง Fail ทันที** และยิงแจ้งเตือนเข้า Discord/Telegram Webhook ของทีม เพื่อให้ระบบหยุดทำงานอัตโนมัติและป้องกันความเสียหายลามปาม

#### **ขั้นตอนที่ 2 (RoE สูง): เคลียร์คลิป Rogue และเปลี่ยนสถานะ**
* **กระทำ:** ยิงสคริปต์เปลี่ยนสถานะคลิปแปลกปลอม (เช่น `vBEB2dIe7ls`, `8Bk78uxlmXw`, `o04srYxc0Ik` ใน ch4 และ `7Cm9QOX-PGo`, `wDPTTfwQNJY`, `LpGgxyuWBLc` ใน ch1) ให้เป็น `privacyStatus: private` ทันที

* **เงื่อนไขการสั่ง FAIL ของ Guard (Must FAIL Criteria):**

   * **เหตุผล:** การเปลี่ยนคีย์ใน GitHub ไม่ได้ยกเลิกสิทธิ์ของ Refresh Token ที่หลุดออกไป สคริปต์ปริศนาที่นาที `:21` จะยังคงใช้อัปโหลดได้ตามปกติ
