## คำตอบที่ยืนยันได้ (Microsoft Learn + Gemini ตรงกัน)

**Smart App Control ไม่มี allowlist** — มีแค่ **On / Evaluation / Off** และบล็อก binary ที่
ไม่ได้เซ็นโดยปริยาย (Learn: *"unknown, unsigned code are blocked by default"*). ⇒ **ไม่มีทาง
อนุญาต `Runner.Listener.exe` ตัวเดียวโดยไม่ปิด SAC** — และ **ปิด SAC แล้วเปิดกลับไม่ได้**
(ต้องลง Windows ใหม่)

การแยกแยะ definitively:

| ตรวจ | ค่า | แปลว่า |
|---|---|---|
| `...CI\Policy\VerifiedAndReputablePolicyState` | 2 = On, 1 = Evaluation, 0 = Off | SAC |
| `Win32_DeviceGuard.UsermodeCodeIntegrityPolicyEnforcementStatus` | 2 = enforce | WDAC UMCI |
| Event Viewer → CodeIntegrity → Operational | **3077 = block**, 3076 = audit | ตัวชี้ขาดว่าใครบล็อก |

- **ถ้าเป็น WDAC** (มี supplemental policy ได้): reversibly อนุญาตได้ด้วย
  `New-CIPolicy ... -ScanFolder C:\actions-runner` → `ConvertFrom-CIPolicy` →
  `CiTool --update-policy`; undo = `CiTool --remove-policy <id>`
- **GitHub ไม่มี runner ที่เซ็นชื่อ** และ Microsoft ไม่มี wrapper สำหรับ WDAC/SAC ⇒ ทาง
  runner ตันจริง

## P — Problem

## C — Cause (วัดจริง ไม่เดา)

   ปิด SAC = ถาวร (ลง Windows ใหม่). ⇒ **ทาง runner ตันจริง** ไม่ใช่ทำไม่เป็น
