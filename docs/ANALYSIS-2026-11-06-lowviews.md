# วิเคราะห์: ทำไมคลิปเก่ายอดวิวน้อย (2026-11-06)

> วัดจาก YouTube Data API: ทุกคลิปทุกช่อง (206 คลิป) — วิว, วันที่โพสต์, ความยาว, แท็ก.
> ตัวเลขทั้งหมดวัดจริงวันนี้. ที่ปรึกษา panel ยังไม่ได้ข้อสรุปจาก AI เพียงอย่างเดียว —
> ตัวเลขชี้ชัดกว่า.

## สรุปสั้น: "ยอดน้อย" ไม่ใช่เพราะคอนเทนต์ — เพราะ "โพสต์รวดเดียวทีละเยอะ"

## หลักฐานชี้ขาด — วิว vs จำนวนคลิปที่โพสต์ในวันเดียวกัน

| จำนวน Shorts/วัน | n (คลิป) | วิว median |
|---|---|---|
| 1-5 | 20 | 14 |
| 6-10 | 13 | **317** |
| 11-20 | 20 | **334** |
| 21-40 | 25 | **221** |
| **41+** | **89** | **1** ← ทรุด |

**วัน 2026-11-05 = โพสต์ 89 Shorts ในวันเดียว → median เหลือ 1 วิว** (ดีสุดในวันนั้น 711,
แย่สุด 0). เทียบวันปกติที่โพสต์ 6-25 คลิป = median 221-334.

ในบรรดา 53 คลิปของ dharma วันที่ 05: **42/53 ได้ ≤3 วิว** และ**31/53 ได้ 0 วิว**.

## สาเหตุราก (root cause) — เจอในโค้ด

1. **`scripts/publish_shorts.py` ตั้ง `--per-run` default = 0** (= "อัปโหลดทั้งหมดที่ค้าง")
   ⇒ ถ้าไม่มีใครส่งค่า ก็เททั้ง pool ออกมา.
2. **`publish-shorts.yml` ตั้ง trigger `push` ให้ไฟล์ manifest ที่ "workflow เองเป็นคน commit"**
   (`content/ch2_shorts.json` ฯลฯ) ⇒ **ทุกครั้งที่ publish สำเร็จ มัน trigger ตัวเองอีกรอบ**.
3. เมื่อ `grow-shorts-pool.yml` เพิ่ม pool → push trigger ยิง publish ทันที **โดยไม่ส่ง per_run**
   → default 0 → **เท 89 คลิป**.

⇒ เป็น **บั๊กของ rail** ไม่ใช่เพราะคอนเทนต์แย่. คลิปเดียวกัน ถ้าปล่อยวันละ 2-5 จะได้หลักร้อยวิว.

## ปัจจัยรองที่วัดได้

- **ความยาว Shorts:** 16-30 วิ median 187 · 31-45 วิ median 107 · **46-60 วิ median 2**
  (แต่ 46-60 วิ เกือบทั้งหมดอยู่ใน batch วันที่ 05 → ผลนี้ปนกับ effect การเททีละเยอะ).
- **คลิป 61-300 วิ = "โซนตาย":** ไม่ใช่ Short (ไม่ขึ้นฟีด) และไม่ยาวพอเป็น long-form →
  median 2 วิ. ตัวอย่าง: `ไผ่ที่รอสี่ปี` 79 วิ = 0 วิ; `สะพานใบไม้ที่หายไป` 73 วิ = 2 วิ.
- **long-form 10-11 นาทีได้ median แค่ 2** (ไม่ถูกค้นพบ + retention ต่ำ).
- **แท็กครบทุกคลิป** (50/50 ของคลิปตายมีแท็ก) ⇒ **ไม่ใช่ปัญหาขาดแท็ก**.
- **ไม่ใช่ปัญหาความเป็นส่วนตัว** — 49/50 คลิปตายเป็น public.

## การแก้ (ทำแล้ววันนี้)

1. ✅ **`--per-run` default = 2** (drip). จะเททั้งหมดต้องสั่ง `0` เองชัด ๆ.
2. ✅ **ลบ manifest ออกจาก `push.paths`** → หยุดวงจร trigger-ตัวเอง (ต้นเหตุการเท).
3. ✅ **เพิ่ม guard** `scripts/test_publish_shorts_cap.py` — CI จะ fail ถ้า default กลับเป็น 0
   หรือมี manifest ใน push.paths (พิสูจน์แล้วว่าจับบั๊กได้ทั้งสองเงื่อนไข).
4. ✅ ใส่ guard เป็น step ใน `publish-shorts.yml` ก่อนขั้น Publish.

## บทเรียน (จดจำ)
- **ความเร็วที่ปลอดภัย ≈ 6-25 Shorts/วัน/ช่อง** (median วิวสูงสุดในช่วงนี้).
  **ห้ามเท >40/วัน** — ฟีด Shorts ลงโทษช่องที่ท่วม.
- **workflow ห้าม trigger ด้วย output ของตัวเอง** (manifest) — ไม่งั้น cascade.
- **default ที่ปลอดภัยต้องเป็น "drip" ไม่ใช่ "ทั้งหมด"** — ค่าที่หายไปต้องไม่กลายเป็นท่วม.

## ข้อควรทำต่อ
- ปล่อย pool ที่ค้างอยู่ออก **วันละ 2-5 คลิป** (rail ทำเองแล้ว) อย่าเท.
- คลิป "โซนตาย 61-300 วิ" — ตัดให้ ≤60 วิ (เป็น Short) หรือรวมเป็น long-form อย่าปล่อยลอย.
