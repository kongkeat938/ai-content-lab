# ใบสั่งงานมือถือ — ตัด rogue uploader (ทำจากมือถือได้, ~5 นาที)

อัปเดต 2026-11-15 โดย `ak`. ทุกอย่างด้านล่างคือ **สิ่งที่ ak ทำแทนไม่ได้** เพราะเป็นหน้า
ของบัญชี Google / GCP ที่ต้องเป็นมือคุณ (ak เข้าไม่ได้ — วัดแล้ว: `cloudresourcemanager` 403,
และ Google บล็อกการล็อกอินจาก host นี้).

## สั้น ๆ ก่อน
มี "แอปที่เชื่อมบัญชี Google" ตัวหนึ่ง (ชื่อฝั่งเราคือ **Dharma Bedtime Publisher**, อยู่ใน GCP
project `888023422403`) ที่ยังถือสิทธิ์โพสต์ขึ้นช่องเรา แล้วมีคนอื่นใช้มันอัปโหลดคลิปแปลกปลอม
(`en-US`, category 27, โพสต์นาทีที่ `:21`). **เราซ่อนคลิปได้ทุกชั่วโมง แต่ตัดต้นตอไม่ได้** —
ต้องคุณกดในมือถือ.

ช่องที่โดน: **genx** · **dharma** · **kongkeat-story** (คนละบัญชี Google กัน)

---

## ทางที่ 1 — ตัดให้ขาด (แนะนำ): หมุน client secret ใน GCP

ทำครั้งเดียว ตัดได้ทุกบัญชีพร้อมกัน (ทุก token ที่แอปนี้เคยออกให้จะใช้ไม่ได้ทันที).

1. มือถือ → เปิด **console.cloud.google.com** → ล็อกอินบัญชีที่เป็นเจ้าของโปรเจกต์
   (บัญชีเดียวกับที่ใช้ทำช่องหลัก)
2. เลือกโปรเจกต์ **`888023422403`** (มุมซ้ายบน)
3. เมนู ☰ → **APIs & Services** → **Credentials**
4. ใต้ **OAuth 2.0 Client IDs** แตะตัวที่ชื่อ **Dharma Bedtime Publisher**
5. กด **RESET SECRET** (หรือ "Add secret" แล้วลบอันเก่า)
6. **คัดลอกค่า secret ใหม่** แล้วส่งให้ `ak` (ในแชตนี้) — ak จะเอาขึ้น GitHub secret
   `YT_CLIENT_SECRET` ให้เองได้

> ⚠️ ขั้นนี้ทำให้ **token เดิมของเราตายทั้งหมด** (รวมที่แอปเดียวกันออกให้) — ต้องทำข้อ 2 ของ
> ทางที่ 1 ต่อทันที ไม่งั้น rail เราจะหยุด

### ต่อด้วย: re-consent 3 ช่อง (ให้ token ใหม่กับเรา)
ทำบนมือถือได้: เปิดลิงก์ consent แล้วล็อกอินบัญชีของช่องนั้น กด "อนุญาต".
ak จะสั่งรัน `python3 scripts/yt_auth.py --slug <ch>` ให้ เพื่อให้ได้ลิงก์ consent สด ๆ ส่งมาให้
(หรือคุณเปิดเองจาก `docs/CHANNEL-ADMIN-2026-11-06.md`). ทำทีละช่อง:

| ช่อง | บัญชี Google |
|---|---|
| genx | (บัญชีหลักของคุณ) |
| dharma | บัญชี dharma |
| kongkeat-story | บัญชี kongkeat-story |

หลัง consent เสร็จ ส่ง **refresh token** ของแต่ละช่องมาให้ ak (หรือ paste ลง GitHub secret
`YT_CH1_REFRESH_TOKEN` / `YT_CH2_REFRESH_TOKEN` / `YT_CH4_REFRESH_TOKEN` เอง)

## ทางที่ 2 — ถ้าอยากเร็ว/ปลอดภัยกว่า: แค่ "ถอดสิทธิ์แอป" ทีละบัญชี

ไม่แตะ GCP แต่ต้องทำ 3 บัญชี. หลังถอดสิทธิ์ rail ช่องนั้นจะหยุด จนกว่าจะ re-consent (เหมือนทาง 1).

ทำซ้ำ 3 ครั้ง (คนละบัญชี):

1. มือถือ → **myaccount.google.com** → ล็อกอินบัญชีของช่อง
2. แตะ **ความปลอดภัย (Security)** → เลื่อนลงหา **แอปของบริษัทอื่นที่เชื่อมต่อ (Third-party apps)**
   → **การเชื่อมต่อของคุณกับแอปของบริษัทอื่น**
3. หาแอปที่ชื่อเหมือน **Dharma Bedtime Publisher** (ตัวที่โพสต์ YouTube) → แตะ → **ลบการเข้าถึง (Remove access)**
4. ทำซ้ำกับอีก 2 บัญชี

## หลังทำเสร็จ — บอก ak แค่นี้ก็พอ
พิมพ์มาแบบนี้: `"หมุน secret แล้ว"` หรือ `"ถอดสิทธิ์ครบ 3 บัญชีแล้ว"` (+ วาง secret/token ใหม่ถ้ามี).
ak จะ:
- อัปเดต GitHub secret ให้
- รัน `python3 scripts/rogue_watch_rss.py --alert` + `scripts/audit_channels.py` ดูว่า stream หยุดจริง
- ถ้ายังมีคลิปใหม่ = ยังไม่ขาด → จะรายงานกลับทันที (ตัววัด: ต้องไม่เหลือคลิปใหม่ที่ `:21`)

## ตัววัดว่าสำเร็จ (ak จะยืนยันสดให้)
- RSS/audit: ไม่มีคลิปใหม่ที่ repo ไม่รู้จัก อีกเลย (ตอนนี้ขึ้น "no live rogue upload")
- ถ้ามีโผล่ = ยังไม่ตัดขาด (แปลว่า rogue ถือ grant ของตัวเอง → ต้องหมุน secret ที่ GCP เท่านั้น)
