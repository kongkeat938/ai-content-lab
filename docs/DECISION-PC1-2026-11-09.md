# DECISION — PC1 ใช้ไม่ได้ → เอาไงต่อ (2026-11-09)

K: *"ตอนนี้เจอปัญหา k ใช้ pc1 ไม่ได้แล้วเอาไงต่อ"*

คำตอบสั้น: **ไม่ต้องทำอะไรกับ PC1 — งานที่ต้องใช้มัน (อ่านเมล์) ย้ายขึ้นคลาวด์ไปแล้ว.**
งานทุกอย่างที่ยังต้องเดินอยู่บน GitHub Actions ทั้งหมด; PC1 เป็นของ *ทางเลือก* ไม่ใช่ของบังคับ.

---

## P — Problem
K เข้า/ใช้ PC1 ไม่ได้ (เครื่องล็อกอยู่ / ไม่มีใครนั่งหน้าเครื่อง). แผนก่อนหน้า (ให้ K รันสะพาน
PowerShell 1 บรรทัด) **จึงทำไม่ได้** ⇒ ต้องรู้ว่ายังมีอะไร "ตาย" เพราะไม่มี PC1.

## C — Cause (วัดจริง)
PC1 เดิมถูกใช้ 2 อย่าง:
1. **อ่านเมล์ 3 บัญชี** (Chrome login ค้าง) — งาน *โหลด-bearing* เดียว
2. ขับ **ChatGPT / YouTube Studio UI** (impressions, CTR, รายได้) — งานที่ API ไม่มี

และช่องทางสั่งงาน PC1 ตายหมด: runner = 0 (SAC บล็อก exe ที่ไม่เซ็น), tailnet funnel = NXDOMAIN,
pod = HTTPS egress เท่านั้น.

**แต่ (1) ไม่ต้องใช้ PC1 อีกแล้ว:** `account-watch.yml` รันบน **ubuntu-latest** และอ่าน IMAP ได้เอง
ผ่าน secret `IMAP_ACCOUNTS` — วัดสดวันนี้: อ่าน **kongkeat.938** (genx), **farmmer.938** (dharma),
**kongkeat.p3** (ch4) ครบ, ไม่มี "BLIND", รันทุก ~2 ชม. `mail_watch.py` **ไม่มีโค้ดแตะ PC1 เลย**
(มีแต่ IMAP + Data API).

## S — Solution
1. **ไม่ต้องแตะ PC1.** งานที่ต้องเดิน = บน Actions. PC1 = ทางเลือก.
2. **แก้เอกสารให้ตรงความจริง:** คอมเมนต์ใน `account-watch.yml` ยังบอกว่า "mail อ่านได้แค่บน PC1"
   → แก้เป็น "อ่านจากคลาวด์แล้ว" (กัน agent/คนอ่านเข้าใจผิดว่ายังต้องพึ่ง PC1).
3. **งาน Studio-only** (impressions/CTR/รายได้) ยังทำไม่ได้แบบไร้คน — **ไม่ใช่ตัวคอขวดของ YPP**
   (YPP = 1,000 subs + 4,000 ชม.ดู) ⇒ พักไว้ก่อน; รอ K เปิด Studio หรือเปิดช่อง API เรื่องรายได้.
4. ถ้าวันหน้าอยากได้ PC1 กลับ: ต้องมีคนหน้าเครื่อง **ครั้งเดียว** (สะพาน PowerShell ที่สร้างไว้) —
   **ไม่ใช่ตอนนี้**.

## E — Execute
- แก้คอมเมนต์ `account-watch.yml` (mail = cloud, ไม่ผูก PC1) — commit นี้
- อัปเดต `MEMORY.md` § PC1 ให้ชี้ว่า "ย้ายขึ้นคลาวด์แล้ว; K เข้าไม่ได้ก็ไม่เป็นไร"
- เก็บสะพาน `ops/pc1_agent_bridge.ps1` ไว้ (ใช้เมื่อมีคนหน้าเครื่อง) — ไม่ลบ
