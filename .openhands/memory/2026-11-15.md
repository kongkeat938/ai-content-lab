A third party still uploads Shorts to our channels (fixed `:21`, `en-US`, cat 27).
`rogue-guard` hides each within the hour, but the root fix is the owner's 2-minute
browser step (revoke grant at `myaccount.google.com`, or rotate the GCP client
secret). Measured 2026-11-12: no API key we hold can do it (`cloudresourcemanager`
403). Policy: YouTube spam/deceptive + account-security → termination risk. This is
the #1 thing to close and it needs K, not ak.

**2. Owner's real gmail addresses in this PUBLIC repo (~107 lines).** No password or
token is committed (scanned), but the addresses are a phishing/social-engineering
target and a GitHub acceptable-use concern. Closing it = remove from files AND
history (`git filter-repo`) — a history rewrite, proposed to K, not done unattended.

**3. Reused narration across long-form cycles — watch, not a defect yet.** The 30-125
min sleep compilations repeat the same narrated pieces (rotated order) and YouTube's
2025 "inauthentic / repetitious content" policy targets exactly that. We are a long
way from monetisation, so it is a watch item: each new build should keep adding NEW
pieces, not only re-cycling the same set.

**Cleared by measurement:** no engagement-fraud primitive in the code (no buying
views/subs/likes, no bot traffic, no sub4sub); the ONLY engagement API write is a CTA
