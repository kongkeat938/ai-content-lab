## Root cause of the "rogue uploads" (audit_channels.py)
`publish-shorts` checks out `fetch-depth: 1`; `git pull --rebase` on a shallow clone = **exit 128**, so
`publish_shorts.commit()` lost the id AFTER the upload. Runs 45976910714 (3 clips) and 45920426320 (2)
published fine but recorded nothing → the next audit read them as "UNRECORDED rogue uploads".

## Round 2 (same day) — the commit path was still broken, and why
The run triggered by #58 (46021603269) logged `manifest commit failed after 3 attempts` on BOTH channels,
then the workflow's own commit step pushed "on attempt 1". So the shallow-clone fix was not the whole story:
`commit()` fires while art/bed/reception/upload_log are still unstaged, so `git pull --rebase` dies with
"You have unstaged changes" -- no retry can fix that. Fix: `commit()` now stages `content/` too (still no
--autostash; a clean tree makes a stash unnecessary), and the rebase error is printed instead of swallowed.
`test_manifest_push.py` gained a REAL-git round trip (bare origin + racing commit + dirty tree): 13/13 pass,
and 4/13 fail with the staging line removed -- the guard can FAIL.
