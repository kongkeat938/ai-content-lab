## The bug that mattered: a write path gated by a read call's quota
`yt_auth.load_credentials()` verifies the token's channel with `channels.list`, which
is **quota-limited**. With the shared quota spent it cannot tell which channel a token
owns and **exits** — so publishing died on a spent *read* quota even though
`videos.insert` has its own bucket and would have worked. Fix: take the access token
straight from the refresh token in the env; treat a 403 on the channel check as
"skipped, the per-channel secret pins the target", not a wrong channel. **Rule: never
gate a write path on a read call's quota.**

## Rail generalised to ch1 — first real GenX Shorts are live (2026-11-03)

**Two real bugs found by running the pipeline instead of reading it.**
1. `make_short.py` **never worked from a relative path**: ffmpeg's concat demuxer
   resolves a relative path *inside the list file* against the list file's own
   directory, so `work/.../seg_00.mp4` became `work/.../work/.../seg_00.mp4` and
   every build died with exit 254. Absolute paths fix it. (So the ch2 Shorts that
   *are* live were built by the GitHub runner, whose cwd made the doubling
   harmless — the bug only bites a local build.)
2. **True peak was over the house rule.** The single-pass `loudnorm=I=-14:TP=-1.5`
   left the measured true peak at **-1.3 dBTP**, and the repo rule is ≤ **-3 dBFS**.
   A narrator read has ~18 dB crest factor, so loudnorm alone cannot reach -14 LUFS
   without breaking the ceiling. Working chain: `acompressor=threshold=-24dB:
   ratio=6:attack=3:release=120` → **two-pass** loudnorm (`measured_*` + `offset`,
   `linear=true`) → `alimiter=limit=-3dB:level=disabled`. Measured after: **-15.0
   LUFS / -2.9 dBTP**. Note: -14.0 is not reachable with a hard -3 ceiling on this
   material; the ceiling is the non-negotiable one.

and `publish_shorts.py`; `CHANNELS` dicts hold scripts/manifest/token/work/tags/
