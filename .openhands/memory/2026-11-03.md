## The bug that mattered: a write path gated by a read call's quota
`yt_auth.load_credentials()` verifies the token's channel with `channels.list`, which
is **quota-limited**. With the shared quota spent it cannot tell which channel a token
owns and **exits** — so publishing died on a spent *read* quota even though
`videos.insert` has its own bucket and would have worked. Fix: take the access token
straight from the refresh token in the env; treat a 403 on the channel check as
"skipped, the per-channel secret pins the target", not a wrong channel. **Rule: never
gate a write path on a read call's quota.**
