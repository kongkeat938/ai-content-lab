## Bug 1 — the tension hint was keyed to a name nobody used
- `studio_ai.TOPICS_HINT` was keyed `"kongkeat"`, but `question_for()` is always called with the
  Studio id `"ch4"` (main → `question_for(args.channel)`). So the hint never reached the panel.
- The panel then proposed flat warm scenes → `content/insights/ch4.json` was written flat →
  the generator (`gen_short_scripts` `require=_TENSION`) drops them anyway, and `test_pace`
  (the guard) went red. **The bug survived because the guard only checked the *file*, not the
  wiring that produces it.**
- Fix (`scripts/studio_ai.py`): key the hint `"ch4"`, resolve names **both ways** via
  `channel_names()` (ch4 ↔ kongkeat-story ↔ kongkeat), add `required_hook()` (reads the
  generator's own rule instead of a 3rd copy), `fallback_topics()` + `filter_topics()` so a
  rule-bound channel's file is never written with off-rule (or empty) subjects.
- New guard `scripts/test_insights_wiring.py` (deterministic, no LLM): the hint reaches the
  prompt, off-rule subjects are dropped, an all-flat answer falls back, a channel with no rule
  is untouched. **Proved it FAILs on the pre-fix code** (git stash) — 3 checks red.

## Bug 2 — `advise.ADVISORS` had no `"gemini"` key
- Found while verifying bug 1 live: the panel printed only `### pollinations`. Measured:
  `advise.ADVISORS` keys are `gemini-3.5`, `gemini-3.1`, `gemini-flash`, `gemini-preview`,
  `openrouter`, `pollinations`, ... — **no plain `"gemini"`**.
- Four scripts asked for `"gemini"` by literal name and each did `advise.ADVISORS.get(name)` +
  `if not fn: continue` → **silently skipped** → the "panel" ran on **pollinations alone**
  (66 s, one vendor) or **nothing** when pollinations 400'd on a long prompt (seen live:
  `wrote .../kongkeat-story.json` after only pollinations answered).
- Live evidence: `docs/STUDIO-AI-ch4.md` (run 2026-11-11T01:28Z) and `docs/REVIEW-ch4.md` show
  only `### pollinations`. So the learning loop (topics) AND the grader (`video_review` A–D)
  had a **single-vendor** panel for days.
- Why it survived: `test_advise_panel.py` guards this exact class (its docstring names a past
  `gemini-latest` miss) but only checked `FAST`/`BROAD`/`DEEP` — **never the names the scripts
  actually pass**.
- Fix: add the `"gemini"` alias to `ADVISORS`; add `advise.LIGHT = ["gemini","pollinations"]`
  as the one shared light team; add `advise.advisor(name)` that **raises KeyError** on an
  unknown name (a wiring bug, not a dead vendor); switch all 4 call sites
  (`studio_ai`, `video_review`, `diagnose_videos`, `panel_scorecard`) to `advise.LIGHT` +
  `advise.advisor()`. `panel_bench` keeps `.get()` (it scores an explicit list, fine).
- Guards added to `test_advise_panel.py`: LIGHT names exist, LIGHT is ≥2 and spans 2 vendors,
  `advisor()` is loud, and the 4 scripts must not hardcode `("gemini", "pollinations")`.
  **Proved the LIGHT guard FAILs on pre-fix code.**
