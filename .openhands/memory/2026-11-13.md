## The defect found (and fixed)

A **refresh token is bound to the OAuth client that minted it**. The manager consented
on OAuth client **B** (`888023422403-7g6258s…`, app `ax-content-lab`, in env
`CLIENT_SECRET`); it exchanges `200` there but **`401 unauthorized_client`** on the
primary client **A** (`888023422403-39ngdj…`, app "Dharma Bedtime Publisher", in env
`YT_CLIENT_ID`/`YT_CLIENT_SECRET`), which all three primary channel tokens use.

`delegate_ready.py` checked the alt token with client **A only** → it read NOT-DELEGATED.
Worse: its `exchanges()` returned `True` unless the body contained `invalid_grant`, so a
`401 unauthorized_client` would have read as a **false READY**. Both fixed:

- `delegate_ready.py` now tries `YT_ALT_CLIENT_ID`/`YT_ALT_CLIENT_SECRET` first, then the
  primary client, and requires a real `access_token` (`json…get("access_token")`) — any
  non-200 or body without `access_token` is NOT-DELEGATED.
- `test_delegate_ready.py` proves **both** directions offline (monkeypatched `exchanges`):
  matching client → READY; primary-client-only → NOT-DELEGATED.
- `account-watch.yml` passes `YT_ALT_CLIENT_ID`/`YT_ALT_CLIENT_SECRET` to the step.
- Secrets added: `YT_ALT_CLIENT_ID`, `YT_ALT_CLIENT_SECRET`, `YT_CH1_ALT_REFRESH_TOKEN`.

Panel (4/5 answered, all agreed) recommended exactly this: accept two OAuth clients and
let each token be exchanged with its own. Option (b) "wait for a reachable redirect on
client A" is a dead end: client A is type **web** and rejects every redirect URI
reachable from a recycled pod (all `redirect_uri_mismatch`; loopback → `invalid_request`).
