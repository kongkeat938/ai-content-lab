## Round 7 — a double publish, found and fixed at the root
At 04:46:16 UTC the CI rail published dharma script 163 and at 04:46:19 my manual run published the
same script: **two identical Shorts**. Cause, measured: `publish-shorts.yml` had a `push` trigger on
`content/ch*_shorts/scripts.json` **and** `scripts/publish_shorts.py` — so the pool-grow commit and my
own merge of the cap change each fired the rail, while my pod ran a manual publish from a tree 35
commits behind (its manifest said "unpublished").

Fixed: (1) no `push` trigger — schedule (08:30/16:30/00:30 Thai) + dispatch only; (2)
`published_on_origin()` — the loop `git fetch` + reads `origin/main:<manifest>` and skips a clip whose
id is already recorded there, before spending a render; (3) `--dry-run` no longer writes the
reception ledger (that is what put an uncommitted file in the tree); (4) guard
`test_publish_shorts_cap.py` now fails on a push trigger, on a missing/too-late remote check, and on
an ungated reception write (each verified to FAIL against the unfixed file). Duplicate
`PLdOmK_MRG8` set **private** via `delete_video.py --unpublish` (backup kept); canonical
`K27RC5Tsehc` stays public. 140 dharma / 115 genx Shorts live.
