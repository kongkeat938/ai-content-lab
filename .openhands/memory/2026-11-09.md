# 2026-11-09 — the foreman was down ~6 h; a committed git conflict

## 🔴 Root cause (found and fixed)
`content/upload_log.json` on **main** contained raw git conflict markers
(`<<<<<<< Updated upstream` / `>>>>>>> Stashed changes`). Every foreman run from
**19:35Z 2026-11-08** died with `json.decoder.JSONDecodeError: Expecting value:
line 6 column 1` inside `publish_shorts.uploads_in_last_24h` → `_seed_ledger` →
`_load_upload_log`. **No rail was driven from the chain for ~6 h** (7 consecutive
foreman failures). Nothing else was broken — the schedule-driven rails still ran.

**How it happened:** `scripts/publish_shorts.py::commit()` did
`git pull --rebase --autostash`. Two channel jobs race; the autostash pop left
conflict markers in the dirty ledger, and the next `git add content/upload_log.json`
(remake-shorts) committed them → `612f185 remake(dharma): count Short 34 toward the cap`.

## ✅ Fix (d3e2121)
- Repaired the ledger by **unioning both sides** (append-only file → both stamps real).
- `commit()` now does a **plain `--rebase`** (no `--autostash`): a dirty tree fails
  loudly instead of silently leaving markers. Added `_union_resolve_upload_log()`
  so if markers ever appear they are merged (both sides kept), not committed.
- Added **`scripts/test_repo_hygiene.py`** (runs in `selftest.yml`): fails if any
  tracked file has a line-start conflict marker, or any `.json` fails to parse.
  Anchored `^(<{7} |>{7} )` so a detector's own string literal doesn't trip it.
- Verified live: foreman dispatched **3** rails (publish-ch1, apply-packaging,
  remove-bad-cut) — all three runs **success**. Foreman run itself: success.

## ⚠️ Lesson
The foreman's health step already *anticipated* a rebase conflict on the generated
`docs/HEALTH.md` and aborts gracefully. The **ledger** had no such guard — a
data file written by two racing jobs needs the same treatment. Any file two
workflows commit to concurrently is a conflict risk; guard it at the writer.

### PC1 round 4 — REAL cause: Device Guard blocks the runner exe (not the download)
K's re-run downloaded+extracted fine (my -Clean fix worked) but register failed with:
`config.cmd : 'C:\actions-runner\bin\Runner.Listener.exe' was blocked by your
organization's Device Guard policy.` **Windows (Device Guard / Smart App Control /
WDAC) refuses the UNSIGNED runner binary.** This also explains the first
`CONFIG_FAILED: The system cannot find the file specified` — WDAC surfaces a block

extract (clears Mark-of-the-Web), report Smart App Control
(`VerifiedAndReputablePolicyState`) + WDAC enforcement, and a time-boxed
`Runner.Listener.exe --version` probe that raises `DEVICE_GUARD_BLOCK` naming the 3
fixes. Guard test covers all three. **Fixes for K:** try the new script (MOTW), else
turn Smart App Control Off (irreversible) or get a WDAC folder exception; the
