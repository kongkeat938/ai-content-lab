## Fixed a guard that could not fail
`test_night.py` built its "video longer than audio" case with `-stream_loop -1 ... -shortest`,
which collapses the output back to the audio length — so the case was never built and the
check could only ever see a good file. Measured: the produced file was 6.000 s / 6.000 s.
Rebuilt with an explicit `-t audio+4`; the verifier then correctly reports
`video/audio length differ by 4.00s`. **The verifier was never wrong; the test was.**

against a bicubic blow-up of the *same* frame instead. See `topics/06`.
